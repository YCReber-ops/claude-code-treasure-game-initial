檢查目前修改的程式碼,列出潛在問題。只做檢查,不要修改任何檔案。

## 步驟

1. 找出修改的範圍:
   - 若專案是 git repository:執行 `git status --short` 與 `git diff HEAD`(含已暫存與未暫存的變更)。
   - 若不是 git repository:改用 Glob 找出 `src/`、`server/` 內最近修改的檔案,並說明你是以此判斷範圍。
   - 若使用者在指令後面附了檔案或目錄(`$ARGUMENTS`),只檢查該範圍。
2. 讀取每個被修改的檔案的完整內容,不要只看 diff 片段,確認上下文。
3. 依下列面向檢查:
   - **正確性**:邏輯錯誤、邊界情況、狀態更新順序、非同步競態(例如 React `useEffect` 依賴、updater 內的副作用)。
   - **安全性**:輸入驗證、SQL 注入(是否使用參數化查詢)、密碼與 token 處理、是否洩漏個資(如 E-mail)。
   - **錯誤處理**:`fetch` / API 失敗時的行為、未捕捉的例外。
   - **型別與 API 一致性**:前端 `src/lib/api.ts` 與 `server/index.mjs` 的欄位、回傳格式是否對得上。
   - **專案慣例**:新函式頂部是否有一行用途與輸入/輸出的註解(見 CLAUDE.md);`vite.config.ts` 的版本別名是否被保留;`src/components/ui/` 是否被不必要地修改。
   - **其他**:無用程式碼、重複邏輯、效能問題。

## 輸出格式(使用繁體中文)

依嚴重程度分組:**高 / 中 / 低**。每個問題用一行描述,格式如下:

`檔案路徑:行號` — 問題說明 → 建議修法

最後附上一句總結(例如共幾個問題、最優先該處理哪一個)。若沒發現問題,明確說「未發現明顯問題」,並列出你檢查過的檔案。不要為了湊數而捏造問題。
